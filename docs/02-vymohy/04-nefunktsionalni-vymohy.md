# 04 · Нефункціональні вимоги

> **Kite** — документація поштової системи · v1.4 · затверджено · 17.11.2026

Цілі задані для локального стенду на одному ноутбуці (16 ГБ RAM) і перевіряються навантажувальним тестом k6; це навчальний масштаб, а не продакшен.

| ID       | Категорія           | Вимога                                                                                                                                                   | Як перевіряємо                                           |
| -------- | ------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------- |
| `NFR-01` | Продуктивність      | Публічне відстеження: p95 < 150 мс при 200 запитах/с                                                                                                     | k6, Grafana                                              |
| `NFR-02` | Продуктивність      | Обробка скану від телефону до запису в таймлайн: p95 < 1 с                                                                                               | Трейс OpenTelemetry від scan-service до tracking-service |
| `NFR-03` | Пропускна здатність | Інжест сканів: 500 сканів/с на хабах сумарно                                                                                                             | Симулятор + k6                                           |
| `NFR-04` | Надійність          | Жодна подія сканування не губиться: outbox у кожному сервісі, Kafka з acks=all, ідемпотентні споживачі                                                   | Тест «вбити сервіс посеред потоку»                       |
| `NFR-05` | Узгодженість        | Між сервісами — eventual consistency, затримка < 2 с; статус відправлення змінює лише shipment-service                                                   | Інтеграційні тести                                       |
| `NFR-06` | Ідемпотентність     | Заголовок Idempotency-Key обов'язковий для операцій із грошима, станом відправлення чи комірки (перелік — 9.1); прийом сканів ідемпотентний за `scanId`  | Контрактні тести                                         |
| `NFR-07` | Безпека             | OAuth 2.1 / OIDC через Keycloak, JWT з короткими токенами (5 хв) і refresh; персонал — обов'язково 2FA (TOTP)                                            | Пентест-чекліст OWASP ASVS L1                            |
| `NFR-08` | Безпека             | RBAC + скоуп локації на рівні сервісу, а не лише шлюзу                                                                                                   | Тести доступів на кожен ендпоїнт                         |
| `NFR-09` | Приватність         | Публічне відстеження не показує телефонів, адрес і повних імен; доступ персоналу до персональних даних пишеться в журнал                                 | Аудит-лог, тести                                         |
| `NFR-10` | Спостережуваність   | Трейси (OpenTelemetry → Tempo), метрики (Prometheus), логи (Loki), дашборди Grafana; кожен запит має trace id                                            | Дашборд «Здоров'я системи»                               |
| `NFR-11` | Доступність UI      | WCAG 2.2 AA: контраст, клавіатура, підписи для скрінрідерів; мінімальна ціль натискання 40 px                                                            | Axe, ручна перевірка                                     |
| `NFR-12` | Локалізація         | Українська і англійська, формати дат, валюти й телефонів для України                                                                                     | Перевірка всіх екранів                                   |
| `NFR-13` | Розгортання         | Увесь стенд піднімається однією командою `docker compose up` з репозиторію `kite-infra`, на готових образах із GHCR; профілі core / full / observability | README, чиста машина                                     |
| `NFR-14` | Якість коду         | Покриття юніт-тестами доменної логіки ≥ 70%; контрактні тести API (Spring Cloud Contract або Pact); Testcontainers для інтеграційних                     | CI (GitHub Actions)                                      |
| `NFR-15` | Версіонування API   | URL-версія `/api/v1`, зворотна сумісність подій у межах major-версії                                                                                     | Ревʼю схем                                               |
| `NFR-16` | Зберігання даних    | Події відстеження — 2 роки; персональні дані неактивних клієнтів анонімізуються через 3 роки                                                             | Задача-планувальник                                      |
